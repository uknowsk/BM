# 경쟁 모델 선별 (Competitor Match) 설계

작성: 2026-10-07. 사용자 요청: 당사 제품 또는 개발 중인 스펙의 최적 경쟁 모델을 선별. 가격대 유사(3단계 분류는 너무 거칠다), 최근 출시, 소비자 호응이 좋은 제품, 브랜드별 신제품을 따로 구분해 업계 트렌드 파악.

## 사용자 결정 (확정)
- 기준(우리 쪽): **소분류 + 핵심 스펙 + 목표 가격을 직접 입력** (앱에 없는 개발 중 제품도 가능).
- 최근 출시: **근사 조합**. 정확한 출시일은 대부분의 사이트가 공개하지 않으므로 사이트 NEW 표시, 사이트가 밝힌 연식/출시일, 설명서·스펙시트 날짜, 앱이 처음 발견한 날짜를 합쳐 '신제품'을 판정하고 **근거와 함께 '추정'으로 표기**.
- 소비자 호응: **브랜드 사이트의 평점·리뷰 수만** (제공하는 곳만, 없으면 '미확인'). 외부 리테일러 리뷰는 이번 범위 밖.
- 가격 조율: **5단계 분류 + 근접도 점수** (사용자가 3단계 대신 5단계로 지정). 단계는 5분위, 그 위에 연속적인 근접도 점수를 반영. ±% 범위 슬라이더로 허용 폭 조절.
- 범위: 우선 **조리기기**. 구조는 다른 대분류에도 쓸 수 있게.
- 5단계는 선별 기능과 기존 검색 화면 모두에 적용(사용자 확정: "5단계"). 검색 화면은 `t1..t5` 밴드(보급·중저가·중가·중고가·프리미엄), 직접 입력은 경계 가격 4개.

## 가격: 5단계 + 근접도 점수
- 5단계(보급 / 중저가 / 중가 / 중고가 / 프리미엄)는 대분류 x 시장(통화)별 가격 5분위로 계산(통화·시장을 섞지 않음, 가격 미확인은 별도). 후보가 5개 미만이면 가능한 단계 수로 줄이고 표시.
- 기준 가격이 속한 단계를 기준 단계로 두고, 후보마다 `단계 차이`(0=같은 단계, ±1=인접)를 표시. 옵션 '기준 단계 +-N 이내만'으로 걸러낼 수 있음.
- 근접도 점수(0~1): 기준가 대비 상대 차이 `d = |price - target| / target`, `score = max(0, 1 - d / band)^2`(band = 슬라이더 ±%, 기본 25%). 같은 단계 안에서도 더 가까운 모델이 위로 올라가고, 경계 부근 제품이 단계 때문에 갈리지 않음.
- 단계 경계는 분위수라 데이터 분포가 바뀌면 변하므로, 화면에 각 단계의 가격 범위를 함께 표시.

## 데이터 계약 (모든 어댑터 공통, 값이 없으면 키를 생략 = '미확인')
`catalog.Candidate.attrs` (목록 단계, attrs_src='listing')와 `schema.ProductRecord` 필드(상세 단계) 양쪽에 같은 이름:
| 키 | 형식 | 의미 |
|---|---|---|
| `rating` | float 0~5 | 평균 평점 (5점 척도로 환산, 10점제 등은 /2) |
| `review_count` | int >= 0 | 리뷰(평점) 수 |
| `is_new` | bool | 사이트가 직접 NEW/신제품/New arrival로 표시한 경우만 True. 표시가 없다고 False로 넣지 말 것(키 생략) |
| `release_date` | 'YYYY-MM-DD' / 'YYYY-MM' / 'YYYY' | 사이트나 문서가 밝힌 출시·연식. 추측 금지 |
| `release_src` | 'site' / 'distribution' / 'doc' / 'sitemap' | 날짜 출처. site=제품 페이지가 출시일/연식을 직접 명시, distribution=사이트 데이터의 제조사 최초 유통일(출시일과 다를 수 있음, GE/Café의 `Product_First_Distribution_Date`), doc=설명서·스펙시트에 인쇄된 발행일, sitemap=lastmod(약한 근거, 점수 x0.6) |
모델번호의 연식 코드 해석은 브랜드별 근거를 확인할 수 있을 때만 별도 모듈로(어댑터에서 추측 금지).
`first_seen`(앱이 처음 발견한 시각)은 어댑터가 아니라 `store.py`가 기록한다. 처음 수집한 브랜드·소분류의 기존 제품은 baseline(신제품 아님)으로 표시하고, 이후 새로 나타난 모델만 '신규 발견'으로 본다.

## 선별 엔진 (`match.py`)
입력: `target = {sub, country/region, price, specs{width_in, capacity_*, fuel, burners, features[...]}, weights, price_band_pct, tier_window}`.
후보 풀: 캐시의 목록 후보(candidates) + 상세 수집 제품(products). 목록 수준 속성만 있는 후보는 스펙 적합도를 '미확인'으로 두고 순위에서 불이익이 아니라 신뢰도 표시로 처리.
점수(0~100), 요소별 분해를 함께 반환해 이유를 설명:
1. 가격: 위의 근접도 점수 (+ 단계 차이 표시).
2. 스펙 적합도: 소분류 불일치는 제외, 폭 등 하드 조건은 허용 오차 밖이면 제외, 소프트 조건(용량, 열원, 버너 수, 기능)은 근접도.
3. 최근성: release_date > is_new > first_seen 순으로 근거를 쓰고 12개월/24개월 구간 점수. 근거 종류를 항상 표기.
4. 소비자 호응: 베이지안 보정 평점 (v*R + m*C)/(v+m) (R=평점, v=리뷰 수, C=전체 평균, m=최소 신뢰 리뷰 수). 리뷰 수가 적으면 평점이 높아도 점수를 낮춤. 데이터 없음은 감점도 가점도 아닌 **중립 점수**(가격 0.2, 스펙 0.5, 최근성 0.35, 호응 0.4)로 처리하고 `coverage`(실제 데이터에 근거한 가중치 비율)를 함께 표시. 알려진 항목만 재평균하면 데이터가 빈 모델이 검증된 모델을 이기는 문제가 생겨(테스트로 확인) 재분배는 쓰지 않음. 사용자가 스펙을 입력하지 않으면 스펙 항목은 계산에서 제외.
가중치는 사용자가 조절(기본: 가격 35, 스펙 30, 최근성 20, 호응 15).
신제품 레이더: 브랜드별 신제품 목록(근거 포함)과, 신제품 안에서 기능 키워드 비율(에어프라이, Wi-Fi, 스팀 등)을 기존 모델과 비교해 트렌드 표시.

## API / 화면
`POST /api/match`, `GET /api/launches`. 새 패널 '경쟁 모델 선별': 기준 입력, ±% 슬라이더, 가중치, 5단계 표시와 순위표(요소별 막대+근거), 브랜드별 신제품 구분, 엑셀 시트 출력.

## 작업 단계
1. 계약 확정(이 문서, schema.py). 2. 어댑터 신호 수집(병렬 에이전트, 어댑터별 파일 소유). 3. store first_seen + match.py + 테스트. 4. API·화면. 5. 통합 검증과 푸시.
